# IML 0.4 measurement, 2026-09-18

Corpora: the 72 golden chains in `corpus/golden/` (unchanged since 0.2) and the 36 golden chains in `corpus/golden-0.4/` (registry digest `88d05d0839c1`, canon commit `127ba56f4eb1`).
Python 3.13.15. tiktoken 0.14.0.

Units: bytes (UTF-8), characters (code points), tokens under the named tiktoken encodings `cl100k_base`, `o200k_base`. Tokenizer scope: the named encodings, not any vendor's billing.

Forms: **I-Lang** is the canonical print (`print_L2`); a source written on several lines (continuation lines starting with `=>`) prints on one line, and the source layout is not measured. **IML 0.4 message** is the compiled message including its header `#iml/0.4/88d05d0839c1 ` (one header per chain). **IML 0.4 document** is the header alone on the first line and then the chains, one per line, measured as one text (the header is paid once); in the per-chain tables the column *IML 0.4 chain line* is each chain as it stands on its line of the document, without the header. **JSON** is the one JSON mapping used as baseline, stated here: `{"c":[{"v":VERB,"t":"@TARGET","r":VERBREF,"m":{key:value}}]}` compact with no spaces, `t`, `r` (the BATC verb reference, new in 0.4) and `m` omitted when absent, entity references as `"@NAME"`, every other value as its content string. For the 72 chains of `corpus/golden/` two records stand alongside: **IML 0.3 message** and **IML 0.3 document**, the same texts under the 0.3 header `#iml/0.3/88d05d0839c1 ` (what 0.3 wrote for these chains, which carry no verb reference), and **IML 0.2 message**, the 0.2 surface (header `#iml/0.2/88d05d0839c1 `), written with the codec's internal `version="0.2"` argument. A verb reference has no 0.2 spelling, so the 0.4 corpus has no 0.2 column.

No figure below carries a claim of any kind; the table is the table (ROADMAP gate: efficiency claim).

Reply cost: not measured in 0.4, the codec makes no model calls (ROADMAP item 13 lists the reply; it is counted when a model reads IML, not here).
